## 二、数据模型

### 2.1 实体关系

```
Org（机构树）
 ├── User（用户）──< Role（角色）──< Permission（权限点）
 ├── TerminalGroup（终端分组）
 │    └── Terminal（终端）
 │         ├── heartbeat / status / hardware
 │         ├── PowerSchedule（定时开关机）
 │         └── ScreenShot（截屏历史）
 └── MediaFolder（素材分类树）
      └── Media（素材，SHA-256 去重）

Layout（节目）
 ├── meta：名称/分辨率/朝向/时长/有效期/播放方式
 ├── Region[]（分区：x,y,w,h,z,循环方式）
 │    └── Playlist
 │         └── Item[]（widget 类型 + 素材引用 + 时长 + 转场 + 条件）
 └── ApprovalFlow（审批记录）

Schedule（排期）
 ├── target：terminal[] / group[] / org
 ├── layout → Layout
 ├── 时间：dateRange + weekdays + timeSlots[]
 └── mode：default / cycle / insert / exclusive（优先级递增）

Task（下发任务）── 状态机 ── TransferLog
Command（指令）── 队列 ── ACK 回执
Alert（告警）
AuditLog / TaskLog / SystemLog（按天 JSONL）
```

## 三、终端通信协议

### 3.1 设计原则

- **纯 HTTP**，不用 WebSocket（老 WebView 兼容性 + 无需第三方库）
- **终端主动发起**所有连接（穿透 NAT / 防火墙友好）
- **幂等 + 断点续传 + 校验**，弱网可靠
- **状态最终一致**：终端以本地缓存为准，联网后向服务端对齐

### 3.2 接口清单

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/api/t/register` | 首次注册，上报硬件指纹，换取 `terminalId` + `token` |
| `POST` | `/api/t/heartbeat` | 心跳（默认 15s），上报状态，返回服务端时间与待办标记 |
| `GET` | `/api/t/manifest` | 拉取当前应播清单（排期已在服务端算好） |
| `GET` | `/api/t/events` | **SSE 长连接**，接收实时指令（插播/截屏/重启…） |
| `GET` | `/api/t/poll` | SSE 不可用时的长轮询降级 |
| `GET` | `/api/t/media/:hash` | 下载素材（支持 Range 断点续传 + 限速） |
| `POST` | `/api/t/ack` | 指令执行回执 |
| `POST` | `/api/t/shot` | 上传截屏 |
| `POST` | `/api/t/log` | 批量上报播放日志（Proof of Play） |
| `GET` | `/api/t/apk` | 检查/下载升级包 |

### 3.3 关键流程

**① 零配置发现与注册**

```
终端启动
  └─> 读本地已保存的服务端地址？
        ├─ 有 → 直连
        └─ 无 → UDP 广播 255.255.255.255:7789
                  内容: "LUMASIGN_DISCOVER"
                    └─> 服务端应答: {"host":"192.168.1.10","port":7788,"name":"总部管理机"}
                          └─> POST /api/t/register
                                { mac, serial, model, androidVersion,
                                  resolution, firmware, storage }
                                  └─> 服务端返回 { terminalId, token, approved:false }
                                        └─> 管理员在后台点「批准接入」
                                              └─> 终端下次心跳得到 approved:true，开始拉节目
```

失败兜底：广播无响应时，终端显示配置二维码 + 手动输入服务端 IP 的界面。

**② 心跳**

```jsonc
// POST /api/t/heartbeat
{
  "terminalId": "t_a1b2c3", "token": "...",
  "playing": { "layoutId": "l_x1y2", "itemId": "i_2" },
  "storageFree": 5368709120,
  "cpuTemp": 47.5,
  "volume": 60,
  "appVersion": "1.0.0",
  "errors": []
}
// ← 响应
{
  "serverTime": 1785000000123,     // 用于时钟校准
  "manifestVersion": 27,            // 变了就去拉 /manifest
  "hasCommands": true,              // SSE 断线时的兜底提示
  "approved": true,
  "heartbeatInterval": 15
}
```

**③ 节目下发（清单 + 素材分离）**

服务端把排期算好，只下发「此刻起该播什么」的扁平清单，终端不需要理解排期规则：

```jsonc
// GET /api/t/manifest
{
  "version": 27,
  "serverTime": 1785000000123,
  "schedules": [
    {
      "scheduleId": "s_1", "mode": "default", "priority": 0,
      "dateRange": ["2026-08-01", "2026-12-31"],
      "weekdays": [1,2,3,4,5],
      "timeSlots": [["08:00","12:00"], ["13:30","22:00"]],
      "layout": { /* 完整 layout JSON */ }
    }
  ],
  "assets": [
    { "hash": "sha256:abc...", "size": 10485760, "mime": "video/mp4",
      "url": "/api/t/media/abc...", "name": "promo.mp4" }
  ],
  "signature": "hmac-sha256:..."   // 防篡改
}
```

终端逻辑：
1. 比对 `assets` 与本地缓存，下载缺失项（Range 续传，校验 SHA-256）
2. **全部素材就绪后**才原子切换清单（避免播到一半缺素材黑屏）
3. 本地排期判定：每秒计算当前应播 layout（`exclusive > insert > cycle > default`）

**④ 实时指令（SSE）**

```
GET /api/t/events?terminalId=xx&token=yy
Content-Type: text/event-stream

event: command
data: {"cmdId":"c_1","type":"insert_message","payload":{"text":"三楼电梯维修",
       "color":"#FF3B30","fontSize":48,"speed":80,"position":"bottom","duration":300}}

event: command
data: {"cmdId":"c_2","type":"screenshot","payload":{}}

event: ping
data: {}          // 每 25s 心跳保活，防代理断连
```

指令类型全集：
`insert_message` `screenshot` `reboot` `restart_app` `volume` `power_schedule`
`sync_time` `clear_cache` `upgrade_apk` `pull_info` `refresh_manifest`
`play_now`（临时插播指定节目）`stop_insert` `set_brightness` `screen_on/off`

执行后必须 `POST /api/t/ack {cmdId, ok, message}`，服务端未收到 ACK 则在 60s 后重投（最多 3 次）。

### 3.4 安全机制

| 环节 | 措施 |
|---|---|
| 终端准入 | 新终端默认 `approved:false`，管理员批准前不下发任何内容 |
| 身份 | 注册时签发 `token`（32 字节随机），每次请求校验；可单终端吊销 |
| 素材完整性 | SHA-256 摘要随清单下发，落盘后校验，不符重下 |
| 清单防篡改 | 清单体 HMAC-SHA256 签名，终端验签通过才应用 |
| 传输加密 | 可一键开启 HTTPS（内置自签证书生成器，终端信任固定指纹） |
| 管理端 | PBKDF2-SHA512 10 万轮加盐哈希；会话 Cookie `HttpOnly`+`SameSite=Strict`；登录失败 5 次锁定 10 分钟 |
| 网络 | 可配置 IP 白名单 / 允许网段 |

## 五、性能与可靠性指标

| 指标 | 目标 | 保障手段 |
|---|---|---|
| 管理端首屏 | < 500ms | 免构建、无框架、CSS/JS 总量 < 180KB |
| 交互动画 | 60fps | 只动 `transform`/`opacity`，`will-change` 精准标注 |
| 服务端常驻内存 | < 150MB | 无 ORM 无框架，素材走流式管道不进内存 |
| 终端指令响应 | < 1s | SSE 长连接推送 |
| 终端离线可播 | 无限期 | 本地全量缓存 + 三级兜底 |
| 素材下发 | 可限速不打满带宽 | 令牌桶（全局 + 单终端两级） |
| 时钟同步误差 | < 100ms | 心跳携带服务端时间 + 往返延迟补偿 |
| 数据备份 | 拷贝一个目录 | 全部数据在 `data/` 下，无外部数据库 |

## 七、部署形态

### 形态 A：桌面 App（推荐，用户选择）
```
Mac:     LumaSign.dmg     → 拖到应用程序 → 双击
Windows: LumaSign-Setup.exe → 下一步安装 → 桌面图标
```
内嵌服务端，启动即用，托盘常驻，可设开机自启。窗口内显示局域网访问地址 + 终端配网二维码。

### 形态 B：绿色免安装（无需 Electron）
```
拷贝 lumasign/ 文件夹到任意位置
Mac:     双击 启动-Mac.command
Windows: 双击 启动-Windows.bat
```
自动检测 Node（未装则提示下载），启动服务并打开浏览器。**这是现场应急最快的方式。**

### 形态 C：局域网共享访问

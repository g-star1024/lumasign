## 1. 分阶段交付

### Phase 0（已交付）— 协议深挖 + 服务端兼容控制层原型
- `Downloads/触拓_协议深挖笔记.md`：注册/发布报文格式。
- `server/lib/siqian.js`：直连客户端 + CMS 模拟 + 发现广播。
- `server/api/siqian.js`：管理端 8 个 API。
- `server/server.js`：接入 + 优雅退出。
- 验证：smoke test 通过（注册/列表/播放/音量/插播/发现）。

### Phase 1 — 服务端 56iq CMS 完整化（核心可用）
1. **节目真实映射**：`programResolver` 从「灵屏终端 + 排期」生成 56iq 节目 → 输出 `resource.xml` + `config.json` + `TaskList.config`（网页/视频/图片类型对齐）。
2. **playlog 接入**：`/TransferFeedback.aspx` 解析后写入灵屏 `playlog` 集合（按 deviceIp 关联终端）。
3. **OTA manifest 真实化**：`EAutoUpdate.xml` 指向灵屏托管的 56iq APK（若有）或占位。
4. **管理端 UI**：设备列表页加「56iq/触拓」分组、控制按钮（播放/音量/插播）、「发现」按钮、实时状态。
5. **配置项**：`settings.siqianPort` / `siqianEnabled` 进系统设置页。

### Phase 2 — 播放端(APK) 56iq 双模
1. **兼容模式开关**：设置页新增「56iq 兼容模式」；开启后 APK 可：
   - 作为 56iq 播放端：拉取 56iq CMS 的 programs/list + resource.xml 并播放；
   - 作为灵屏终端：维持现有行为。
2. **注册向导**：复用 Cordova 桥 `Android.getDeviceInfo()`，未注册时显示向导（指向灵屏或 56iq CMS）。
3. **场景/分屏对齐**：56iq `Scene` / `TaskList` 多任务 → 灵屏 `regions` / `dual_mode`。
4. **插播/音量接收**：处理 56iq `InsertMessage` / `volume` 指令（经灵屏 CMS 转发或直连）。
5. **playlog 上报**：向灵屏 `/TransferFeedback.aspx` 风格端点上报播放日志。

### Phase 3 — 全功能对齐（可选/增强）
1. **XMPP 桥**（可选）：轻量 XMPP 服务端，承接 56iq 实时推送；或确认 HTTP OpenAPI 已覆盖全部现场需求。
2. **多语言扩到 50+**：i18n 词库补齐（复用触拓 languages/ 文件）。
3. **OTA 双向**：灵屏给 56iq 设备推 56iq APK；灵屏自身 OTA 不变。
4. **企业 OAuth**（低优先）：仅当需接入 56iq 公有云账号时做。

### Phase 4 — 联调与现场验证
- 在 **192.168.2.153**（RK312x / Android 4.4 / 触拓 com.dsplayer）真机验证：
  注册 → programs/list 拉取 → 播放 → 插播 → 音量 → 反馈 → OTA。
- 验证灵屏服务端控制台能看到该设备并下发指令。

## 2. 风险与决策点

| 风险 | 说明 | 缓解 |
|---|---|---|
| 56iq 广播包格式未公开 | DEX 仅见标签名，JSON 广播可能不被旧固件识别 | 主用「手动指向 serverHost」；广播作补充 |
| XMPP 私有协议 | 实现成本高、无文档 | 以 HTTP OpenAPI 为主控面，XMPP 列为 v2 |
| APK 无本地构建环境 | 依赖 GitHub Actions CI 出包 | Phase 2 改动经 `android/**`，push tag 触发 CI |
| 4.4 WebView 限制 | Chromium 33 语法限制 | 沿用现有 legacy 引擎构建约束（inset 等） |
| 跨签名 OTA | 触拓 APK 与灵屏签名不同 | 跨签名先 uninstall 再装（沿用 v1.3.24 逻辑） |

# 13 · 重刷固件（RK312x）指南

> 面向：RK3126 / RK3128 白牌标牌板（Android 4.4.4），系统被锁死或起不来，考虑"重装系统"。
> **先读第 0 节。** 90% 的情况不需要刷机，而且乱刷的代价是不可逆的。

---

## 0. 先做判断：**你到底需不需要刷机？**

| 你的需求 | 需要刷机吗 | 该用什么 |
|---|---|---|
| 只想清掉 LumaSign 存的错误服务器地址 / 卸掉它 | ❌ **不需要** | 按住 `RECOVERY` 开机 → Android Recovery → **`wipe data/factory reset`** |
| 想彻底回到出厂状态 | ❌ **不需要** | 同上，`wipe data` 就是恢复出厂 |
| 能进桌面（安全模式等） | ❌ **不需要** | 设置 → 备份和重置 → 恢复出厂设置 |
| **系统分区本身坏了**（Recovery 都进不去、开机卡 logo、反复重启） | ✅ **需要** | 本文第 2 节 |
| 想换成别的系统（如刷通用 TV 盒子固件） | ✅ 需要，但**强烈不建议**，见第 4 节 | — |

### ⚠️ 三个必须先知道的事实

1. **Recovery 和刷机用的是同一个按键。**
   - 按住 `RECOVERY` **开机** → 进 Android Recovery（**不需要固件**）
   - 按住 `RECOVERY` **插 USB** → 进 Loader / MaskROM 模式（**需要固件**）
   - → **所以先试 Recovery `wipe data`，它和刷机一样能"回到出厂"，但零风险。**

2. **刷机同样依赖 USB 能枚举。**
   你现在 `adb devices` 认不到设备，说明要么**线是充电线**（无数据线芯），要么板子的 Android USB 功能没开。
   **关键区别**：`MaskROM` 模式是**芯片内部固化的 ROM**，完全不依赖 Android 系统，也不需要在系统里开"USB 调试"。
   **所以 MaskROM 是检验"线/口到底通不通"的最好试金石**：只要 RKDevTool 报出 `Found One MASKROM Device`，就说明**线是好的**。

3. **没有原厂固件，绝对不要刷。**
   擦除 Flash 之后没有固件可写 = **真砖**（连 Recovery 都没了）。这块是白牌相框板，固件通常只能找**贴牌厂商**要。

---

## 1. （推荐）不刷机的等价方案

按住 `RECOVERY`（板上丝印 `REC` / `RESET` / `RECOVERY` 的按键或小孔）不放 → 插 12V 通电 → 保持 3～5 秒松开 → 进 Recovery 菜单：

```
wipe data/factory reset  →  Yes -- delete all user data
wipe cache partition
reboot system now
```

用 **USB 键盘的方向键 + Enter**（或板上按键：音量± 移动 / 电源 确认）操作。
效果：清空 `/data`，LumaSign 的 `server_url` 一并消失 → 重启后自动走零配置发现 → **屏幕自己复活**。

## 2. 真要刷机：完整流程

### 2.1 需要的材料

| 材料 | 说明 |
|---|---|
| **RKDevTool**（推荐，新版）或 **AndroidTool v2.72**（老版，很多老教程用它） | Windows 端烧录工具 |
| **DriverAssitant**（如 v5.x） | 瑞芯微 USB 驱动，装完设备管理器里会出现 `Rockusb Device` |
| **一根确定能传数据的 USB 线** | 接板子的 **OTG / micro-USB** 口；**不要用充电线** |
| **原厂固件 `update.img`**（整包）或散包（`loader.img` / `boot.img` / `system.img` / `recovery.img` …） | ⚠️ **最关键、也最容易缺的一件** |

> 工具和固件需要**你自己在浏览器下载**（我这边网络出口受限，拿不到瑞芯微官网的资源）。
> 优先找**整机贴牌厂商（触拓 / 零度 / 相框 OEM）**要"固件 + 刷机工具 + 短接点位图"三件套，他们一定有。

### 2.2 进 Loader 模式（优先，最简单）

1. PC 上装好 `DriverAssitant`（运行 `DriverInstall.exe`）。
2. 板子**断电**（拔 12V）。
3. **按住板上的 `RECOVERY` 键不放**。
4. 把 USB 线插到 PC 与板子的 **OTG / micro-USB** 口。
5. 上电，等电脑识别到 `Rockusb Device` / `Loader Device` → 松开按键。
6. 打开 RKDevTool → 顶部应显示 **`Found One LOADER Device`**。

### 2.3 进 MaskROM 模式（Loader 进不去时）

- 板子背面/主控旁通常有一对**裸露焊盘，丝印 `MaskRom`**（或标"短接"的两个小圆点）。
- 操作：板子**断电** → 用镊子**短接这两个点** → **保持短接**状态下插 USB 上电 → RKDevTool 报
  **`Found One MASKROM Device`** → 松开。
- 找不到触点：可以搜 **"RK3128 短接神器"**（免拆短接小板），原理相同、比镊子稳。
- **MaskROM 不依赖 Flash 里任何内容**，所以哪怕系统完全损坏也能刷进去。

### 2.4 烧录

**整包（推荐）：**
1. RKDevTool → **「升级固件」** 页 → 「固件」栏 **打开 `update.img`** → 工具解析出分区列表。
2. **勾选「擦除 Flash」**（保证干净出厂状态，避免旧数据残留导致启动异常）。
3. 点 **「升级」** → 等 3～5 分钟（取决于 USB 和固件大小）。
4. 日志出现"下载完成"后 → **拔 USB、断电、重新上电**。
   > ⚠️ **不要在 MaskROM 模式下点工具里的"重启设备"** ——该指令在 MaskROM 下常常失效，会让你误以为还是黑屏。

**散包（只替换某个分区时）：**
切到 **「下载镜像」** 页，逐个分区指定文件路径 → 点 **「执行」**。

### 2.5 刷完首开机

首次开机比平时慢（要重建 `/data`），**耐心等 1～5 分钟，别中途断电**。
进去后逐项验证：WiFi 能否打开、触摸/遥控是否有反应、声音输出、分辨率是否对、网口是否通。

## 3. 已知坑（社区血泪，照着避）

| 现象 | 原因 | 处置 |
|---|---|---|
| `Download Boot Fail` | **DDR 配置不匹配**（RK3128 对 DDR 频率很敏感：DDR3 400/533MHz、DDR3L 800MHz 等） | 换与硬件版本匹配的 loader / 换固件，**不要反复重试浪费感情** |
| 固定卡在 **17%** | 固件包不完整、`boot`/`system` 分区镜像损坏、或**分区表（parameter）配置错误**导致按错偏移写 | 换完整整包重刷 |
| 进度条长时间不动 | 「擦除 Flash」耗时本来就长 | **多等几分钟**再判断是否真卡死 |
| MaskROM 下"重启设备"无效 | 工具软件重启指令在 MaskROM 下失效 | 手动断电重启 |
| 刷完黑屏但工具显示成功 | 固件与屏/背光/触摸参数不匹配 | 换原厂固件 |

## 4. ⚠️ 为什么**不要**拿"通刷包"去刷一块数字标牌

盒子的"通刷固件"生态很成熟，但它面向的是**机顶盒/投影仪**。数字标牌板上的这些东西**是板级定制的**：

- **LVDS / MIPI 屏参**（分辨率、时序、背光控制）——刷错 = 黑屏或花屏
- **触摸屏驱动**——刷错 = 点不动
- **网口 PHY / WiFi 模组**——刷错 = 连不上网
- **GPIO 按键 / 红外遥控**——刷错 = 按键失效

**结果很可能比现在更糟**：现在至少系统能起、能进 Recovery；刷错通刷包之后可能连 Recovery 都进不去，而你又没有原厂固件可回滚。

**结论：只有拿到原厂 `update.img` 才刷。**

---

## 5. 兜底手段：TTL 串口

如果既进不去 Recovery、也找不到 MaskROM 触点：
板上通常有 **UART 调试串口**（4 pin：`GND / TX / RX / VCC`）。用 **USB-TTL 模块**（CH340/CP2102）接上，用 MobaXterm / SecureCRT 以 115200 波特率连：
- 能看到芯片启动全过程的完整日志，**精确定位卡在哪一步**
  （卡在 `DDR: 256MB` → DDR 参数不匹配；卡在 mmc → Flash 初始化失败；`Loading kernel` 之后停 → 内核不兼容）
- 还能**进 U-Boot 命令行**直接操作分区、改环境变量

这是"看清问题"的终极手段，但需要额外硬件 + 一定门槛。

- [ ] 功能验证：WiFi / 触摸 / 声音 / 网口 / 分辨率
- [ ] 重新配置网络与厂商客户端（刷机后全部配置清空）

## 附：优先级总结

```
Recovery  -> wipe data        ← 首选，零风险，不用固件，效果等同恢复出厂
   ↓ 不行
安全模式  -> 清应用数据/卸载    ← 只需键鼠，不动系统
   ↓ 不行
USB adb   -> uninstall/install ← 最快，但要线能传数据
   ↓ 不行
E版远程   -> UnApkInstall      ← 屏幕上还挂着 E版(XMPP :5222) 时可用
   ↓ 不行
**重刷原厂固件**               ← 需原厂 update.img，本文第 2 节
   ↓ 不行
TTL 串口 / 换板                ← 终极手段
```

## 7. 如何识别固件身份（找厂商要固件时**照抄这几行**）

**不用拆机**——设备只要还能进系统：**设置 → 关于（平板电脑/设备信息）**，抄下这 4 项：

| 抄什么 | 示例（本机实测，2026-09-30） | 作用 |
|---|---|---|
| **版本号** | `rk312x-eng 4.4.4 KTU84Q eng.root.20200828.113332 test-keys` | 产品名 / 构建类型 / 构建用户 / **编译时间戳** / 签名类型 |
| **内核版本** | `3.10.0 root@dyc #230 Tue Aug 31 15:53:03 CST 2021` | 内核版本 + **编译者用户名** + 编译时间 + 构建次数 |
| **供应商软件版本** | `NSD128ds_edpAD/ayljlluncher210831` | **机型串 + 屏接口 + 厂商桌面版本**——厂商认这个 |
| CPU / 内存 / 存储 | `rk312x` / `1G` / `8G` | 硬件规格 |

### 字段怎么读

- **构建类型**：`eng` = 工程版（**出厂即 root、`ro.adb.secure` 常为 0 → adb 免授权且直接是 root**）；
  `userdebug` = 调试版；`user` = 正式发布版。
- **签名**：`test-keys` = 用 AOSP 测试密钥签名，**非厂商私钥** → 系统本身可被改。
- **屏接口**：机型串里的 `edp` / `lvds` / `mipi` 决定屏参类型。
  ⚠️ **`eDP` 屏绝对不能用机顶盒"通刷包"**——通刷包只带 LVDS/HDMI 时序，刷上去这块屏直接不亮。
- **厂商桌面名 + 日期**（如 `ayljlluncher210831`）= 厂商给这台机器定制的 launcher 及其构建日期。

### 本机实测记录（R1 标牌板）

```
CPU            rk312x
运行内存        1 G
总存储          8 G
Android 版本    4.4.4
内核版本        3.10.0 root@dyc #230 Tue Aug 31 15:53:03 CST 2021
版本号          rk312x-eng 4.4.4 KTU84Q eng.root.20200828.113332 test-keys
供应商软件版本    NSD128ds_edpAD/ayljlluncher210831
```

**结论**：这是**小厂白牌整机的 eng + test-keys 固件**。机型串 `NSD128ds`、厂商桌面 `ayljlluncher`
在公网**搜不到任何结果**（无公开固件可下）→ **固件只能找卖家/厂家要**，把上面 4 行原样发给他们即可。

## 8. 进阶：**不刷固件**、只清 `/data` 的两种办法

> 前提：USB 能枚举 + 能进 **Loader / MaskROM** 模式。适合"进不去 Recovery、又不想刷整包"的情况。

### 8.1 通用做法：`rkdeveloptool`（瑞芯微开源工具，跨平台）

```bash
rkdeveloptool ld                 # 列出设备（应显示 Maskrom / Loader）
rkdeveloptool rfi                # 读 Flash 信息（型号/容量）
rkdeveloptool ppt                # 打印分区表 → 找到 userdata / misc 的偏移与扇区数
```

然后二选一：

- **写零破坏 superblock**（让系统下次开机自动格式化 /data）
  ```bash
  # 先造一个 16MB 的零文件，写到 userdata 起始处
  dd if=/dev/zero of=zeros16m.bin bs=1M count=16
  rkdeveloptool wl <userdata起始扇区> zeros16m.bin
  ```
  ext4 的超级块被抹掉 → 开机挂载失败 → Android 会重新格式化 `/data` = **等效恢复出厂**。

- **写 BCB 让 U-Boot 自动执行 wipe**（更干净，交互为零）
  `misc` 分区偏移 0 处写 `boot-recovery`，偏移 32 处写 `recovery\n--wipe_data\n`：
  ```bash
  printf 'boot-recovery\0' > misc.bin
  dd if=/dev/zero bs=1 count=720 >> misc.bin        # 补齐 recovery 字段
  printf 'recovery\n--wipe_data\n' | dd of=misc.bin bs=1 seek=32 conv=notrunc
  rkdeveloptool wl <misc起始扇区> misc.bin
  ```
  下次开机 U-Boot 读到 BCB → **自动进 recovery 并执行 wipe_data** → 重启后就是出厂状态。

> ⚠️ 这两个操作都要**准确的起始扇区**。扇区算错会写到别的分区上（可能损坏 boot/system）→ **写之前务必用 `ppt` 核对，并先 `rl` 读回一份原始数据备份。**

### 8.2 商用工具（更省事）

**Infinity-Box RockChip Service Tool** 这类工具内置了 **`Reset Settings → Wiping UserData`** 操作，
不需要固件、不需要算扇区，识别到设备后直接点一下就把 userdata 抹了（实测在 RK312X NAND 机型上有效）。
代价是要买 dongle。

### 8.3 顺带一个信息通道

**TTL 串口** 除了看启动日志，还能直接在 **U-Boot 命令行**里操作分区；
`fastboot`/`rockusb` 之外，部分板子的 U-Boot 支持 `mmc erase` 之类的命令，可以精确擦除指定分区。

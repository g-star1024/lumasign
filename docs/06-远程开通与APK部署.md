# 06 · 远程开通与 APK 部署指南

## 0. 问题背景（关键约束）

电子屏已嵌墙、无法逐台拆机安装 APK，但**已知全部设备 IP**。目标是：不动墙、不碰屏，把「灵屏 LumaSign 播放端」远程装到每台安卓设备上，并实现 0 成本替换触拓 CHUTO「液晶互动」。

## 1. 技术现实（先说清楚）

安卓的安全模型**禁止任意网络静默装 APK**。要在不接触设备的情况下完成安装，设备侧必须**已存在某种特权或代理**。好消息是——数字标牌设备天然具备这个条件：

- **厂商自带远程升级能力**：触拓 CHUTO 官方文档明确「支持播放端硬件固件及软件程序的**远程升级、安装与卸载**」「局域网内任意支持 web 访问的设备均可对终端进行操作」。即设备本身就支持被远程推送安装。
- **网络 ADB（TCP 5555）**：安卓通用机制，数字标牌 ROM 多半开放或可在设置中开启，是**最稳、最通用**的远程安装通道。
- **厂商 Web 配置页**：部分设备开放本地 HTTP 配置页，可远程上传 APK。

因此我们的策略是**分层兜底、能装就装**：先探测每台设备「支持哪种方式」，再选最强可用通道推送。

## 2. 系统提供的「设备开通」能力

管理端 → 侧栏「**设备开通**」页（对应服务端 `server/api/fleet.js` + `server/lib/fleet.js`）：

1. **扫描**：填入已知 IP 列表（或子网段），逐个 TCP 探测 5555/80/8080/7788/22… 端口，抓取 Web banner 做指纹识别，判断设备类型与可开通方式。
2. **指纹判定**：
   - 开放 `5555` → `adb`（网络 ADB 开通，首选）
   - banner 含「液晶互动 / CHUTO / 触拓」→ `vendor`（厂商 API 开通）
   - 开放 Web 配置页 → `vendor`（尝试厂商升级端点）
   - 已在本系统注册 → `already`（跳过，后续由其自升级）
   - 其余 → `manual`（需一次性开启 ADB）
3. **推送 APK**：选好已上传的播放端 APK（管理端 → 终端 → APK 升级包），点「推送 APK」即执行远程安装。
4. **厂商探测**：对未知设备发「厂商端点探测」，回显其开放端口与 banner，便于我们确认正式升级协议。

## 3. 三条开通通道

### A. ADB-over-TCP（首选，无需物理接触）
- 桌面端内置 `adb`（打包进 `resources/adb`；开发态回退 PATH）。
- 开通命令：`adb connect <ip>:5555 && adb -s <ip>:5555 install -r -g <apk>`（`-g` 自动授予权限，利于 kiosk 自启）。
- **设备侧一次性前置**（可远程完成）：开启「开发者选项 → 网络 ADB 调试 / 无线调试」。部分 CHUTO ROM 默认即开 5555。

### B. 厂商 API 推送（钩子，待确认端点）
- CHUTO 播放端自带远程安装能力。当前 `vendorPush()` 为**探测性实现**：尝试常见 Web 端口并记录响应，**不臆造协议字段**，避免误写导致设备异常。
- 你只需把设备的「Web 配置页地址 / 远程升级端口」告诉我们，即可适配正式推送协议（届时完善 `vendorPush`）。

### C. 厂商 Web 配置页（手动但远程）
- 浏览器打开 `http://<ip>`，在厂商自带升级页上传我们的 APK。无需拆墙，但每台需一次点击。

## 4. 首次开通后的「自维护」

播放端一旦装上并注册到本系统，即获得**完整自管理能力**：
- 后续版本升级：管理端上传新 APK → 终端 `/api/t/apk` 自下载自安装（已内置）。
- 远程指令：重启、截屏、音量、定时开关机、节目切换等（终端 API 已实现）。
- 离线兜底：断网自动播放本地缓存 + 内置兜底页。

即：**首装只需一次远程通道，之后全自动化**。

## 5. 桌面端打包（Mac / Win 双平台）

```
# 开发态运行（零依赖，直接 node）
node server/server.js
# 打开 http://localhost:7788/   默认 admin / admin123

# 打包桌面端（需先 npm install 仅用于构建，不进运行时）
npm install
npm run dist:mac     # 产出 dist/*.dmg / *.zip（x64 + arm64）
npm run dist:win     # 产出 dist/*.exe（NSIS 安装包）
```

- 桌面端主进程**同进程托管** Node 服务端（Electron 主进程即 Node，直接 `import('../server/server.js').init()`），无需单独打包 node 二进制、无需子进程。
- 数据落在 `userData/lumasign-data`（asar 之外，可写）。
- `adb` 经 `extraResources` 打入 `resources/adb`，运行时自动探测；缺失则回退 PATH。
- 图标放在 `desktop/build/icon.icns`（Mac）/ `icon.ico`（Win），缺省不影响功能。

## 6. 实操建议（针对你的场景）

1. 在「设备开通」页填入全部已知 IP，点扫描 → 看指纹判定结果。
2. 凡标 `adb` 的：确保设备已开网络 ADB（多数 CHUTO 默认开），直接「推送 APK」。
3. 凡标 `vendor` 的：先用「厂商探测」看端点，把结果发我们补全协议；或走厂商 Web 配置页上传。
4. 凡标 `manual` 的：找一台样机确认其开启 ADB 的方式（通常设置里一键开），记录后批量可复制。
5. 全部开通后，旧「液晶互动」可保留或经 `adb uninstall <包名>` 卸载（管理端提供卸载入口，谨慎使用）。

> 一句话：**已知 IP + 设备侧已有远程特权 = 可零接触批量装机**。本系统把「探测能力」和「最强可用通道」都做成了界面化操作。

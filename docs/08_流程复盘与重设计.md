# 灵屏 LumaSign · 业务流程复盘与重设计报告

> 审计日期：2026-08-05 | 审计范围：制作→审批→排期→下发→播放 全链路
> 审计结论：**审批模块完全空转，排期绕过审批，列表刷新系统性失效**

---

## 一、用户反馈的三个问题（根因定位）

### 问题 1：新建后必须刷新才能看到内容

**根因**：`views.js` 中 4 个页面用了 `box.replaceWith(view)` 的"一次性渲染"模式。

```
renderSchedules()   → views.js:813  box.replaceWith(view)  ← 第2次调用时 box 已脱离 DOM，静默失败
renderUsers()       → views.js:875  同上
renderLogs()        → views.js:897  同上
renderApprovals()   → views.js:839  同上 + 递归调自己生成无人接手的 DOM
```

DOM 语义：`Node.replaceWith()` 在 `parentNode === null` 时直接 return 不报错。所以新建/删除/操作后的 `reload()` **看起来执行了，但页面纹丝不动**。

**对照**：`renderLayouts()`（views.js:361）和 `renderMedia()`（views.js:276）用的是「稳定 root + `paint()` 重绘子节点」模式，这两个页面的刷新是正常的。

---

### 问题 2：发布审批提示"该节目当前不存在审批状态"

**根因**：编辑器"发布审批"按钮**调错了接口**。

| | 应该调用的 | 实际调用的 |
|---|---|---|
| 接口 | `POST /api/layouts/:id/submit` | `POST /api/layouts/:id/approve` |
| 含义 | "我做好了，请审批"（提交） | "我同意"（批准） |
| 权限 | `layout:submit`（制作人员） | `layout:approve`（审批人） |
| 位置 | admin.js:553（**全项目零前端调用**） | admin.js:575 |

服务端 `admin.js:580` 拦截逻辑：
```js
if (approval.state !== 'pending') return fail('该节目当前不在待审批状态');
```
节目状态是 `draft` 或 `approved`（永远不会是 `pending` 因为没人调过 `/submit`），**100% 必然报错**。

**叠加问题**：系统设置里 `approvalLevel` 默认为 `0`（不审批），且设置页面**根本没有该字段的编辑控件** → 用户无法开启审批。即使开启，前端也没有入口触发 `draft→pending` 的状态转换。

---

### 问题 3：排期下发不用审批直接发布，那审批的意义是啥？

**直说：目前审批没有任何意义。** 原因有两条：

1. **建排期 = 立即下发**（admin.js:688）：`POST /api/schedules` 创建后立刻调用 `pushToTargets()`，不校验 `approval.state`
2. **"下发"按钮是假的**（views.js:788）：只弹 toast 提示，零 API 调用

后端其实实现了带审批校验的真发布接口 `POST /api/schedules/:id/publish`（admin.js:711-721），会检查 `approval.state === 'approved'`，但**从未被任何前端代码调用过**。

## 二、完整状态机（现状 vs 目标）

### 现状状态机（断裂版）

```
新建节目 ──► draft(若approvalLevel≥1) OR approved(若=0)    ← 终态？
  │
  ├─ 编辑保存 ──► 仍 draft / approved（regions变化时approved→draft）
  │
  ├─ [发布审批] ──✗ 调用 /approve ──► 400 "不在待审批状态"   ← BUG！
  │                （应该调 /submit 才能进入 pending）
  │
  ├─ 建排期 ──► 立即 pushToTargets ──► 终端收到              ← 绕过审批！
  │
  └─ [下发]按钮 ──► toast("已下发")                           ← 假按钮！

pending 状态：◼︎ 永远无法到达（无入口）
rejected 状态：◼︎ 死状态（无出口、不在审批中心列表、徽章显示英文原文）
```

### 重设计后状态机（目标）

```
                        ┌──────────────────────────────┐
   新建节目               │  approvalLevel = 0            │
  POST /layouts           │  state = approved（免审直通）  │
                        └──────────┬───────────────────┘
                                   │
                        ┌──────────▼───────────────────┐
                        │  approvalLevel ≥ 1             │
                        │  state = draft                 │
                        └──────────┬───────────────────┘
                                   │
                    编辑保存        │  点击[提交审批]
                   PUT /layouts     │  POST /submit
                        │           │
                        ▼           ▼
                     draft ◄────── pending ◄──┐
                        ^          |          │
                        |     审批通过         │ 多级审批
                        |     (step<level)     │ (step≥level)
                        |          |          │
                        |     审批驳回         │
                        |     POST /approve    │
                        |     pass=false       │
                        |          |          │
                        |          ▼          │
                        |       rejected      │
                        |          |          │
                        |     重新编辑提交     │
                        |     (回到 pending)   │
                        |                      │
                        └──────────────────────┘
                                           │
                                    state = approved
                                           │
                                      ┌────▼────┐
                                      │ 建排期   │ enabled=false（草稿）
                                      │  草稿状态 │ 不推送终端
                                      └────┬────┘
                                           │
                                      点击[发布]
                                      POST /publish
                                      校验 approved ✅
                                           │
                                    pushToTargets()
                                           │
                                      终端收到 & 播放
```

**核心变化**：
1. **建排期 ≠ 发布**：建排期时 `enabled: false`（仅保存配置），点击"发布"才校验审批并推送
2. **提交 ≠ 批准**：制作人点"提交审批"(`submit`) 进入待审；审批人点"批准"(`approve`) 通过
3. **驳回不死**：被驳回的节目可以重新编辑再提交

## 五、重设计后的业务流程（最终态）

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  节目制作  │ ──► │  保存草稿  │ ──► │  提交审批  │ ──► │  审批通过  │ ──► │  建立排期  │
│          │     │ (draft)  │     │(pending) │     │(approved)│     │ (enabled │
└──────────┘     └──────────┘     └──────────┘     └──────────┘     │ =false) │
                                                       │              └────┬─────┘
                                                       │                   │
                                              approvalLevel=0时           │
                                              跳过审批直通               │
                                                                        ▼
                                                                 ┌──────────┐
                                                                 │  发布下发  │
                                                                 │ 校验审批  │
                                                                 │ 推送终端  │
                                                                 └──────────┘
```

**角色分工**：
- **制作人员**（role_maker）：制作 → 保存 → 提交审批（`layout:submit`）
- **审批人**（role_admin）：在审批中心批准/驳回（`layout:approve`）
- **排期管理员**（schedule:edit + schedule:publish）：建排期 → 发布（`schedule:publish` 会二次校验审批）

**闸门**：
1. 提交审批时：`approvalLevel > 0` 才允许（否则提示"当前无需审批"）
2. 发布排期时：`layout.approval.state === 'approved'` 才允许推送
3. 构建终端清单时（schedule.js:91）：未审批节目自动过滤（最后一道防线）

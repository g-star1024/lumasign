# 灵屏 LumaSign · 功能路线图

> 版本：v1.0 ｜ 编制日期：2026-08-05
> 定位：局域网数字标牌管理系统，0 成本替换「数字标牌 e 版（触拓 CHUTO）」
> 规模假设：单一局域网、1–50 台终端

---

## 0. 当前能力盘点（已交付）

先说清楚我们已经站在哪。

| 能力域 | 状态 | 说明 |
|---|---|---|
| 终端管理 | ✅ | 零配置 UDP 发现、心跳、在线状态、远程重启/音量/亮度 |
| 素材库 | ✅ | 上传/去重/缩略图/断点续传/魔数校验 |
| 节目制作 | ✅ | 可视化编辑器，Layout→Region→Item 三层模型 |
| 播放引擎 | ✅ | 一份引擎三处复用（编辑预览＝终端渲染＝浏览器预览） |
| 排期下发 | ✅ | 四种播放方式（default/cycle/insert/exclusive）语义对齐 e 版 |
| 审批流 | ✅ | 提审→审批→自动进入下发列表 |
| 监看墙 | ✅ | 一块大屏监控所有屏，含只读 token 分享 |
| 定时开关机 | ✅ | 安卓端 AlarmManager + 真熄屏（系统签名/root 双路径） |
| 远程开通 | ✅ | 网络 ADB 批量装机 + 厂商 API 探测 |
| 局域网扫描 | ✅ | 自动＋手动，识别安卓/电子屏/已纳管/未知设备，设备台账 |
| 安全体系 | ✅ | 七层纵深防御 + 内容合规三道闸 + 审计哈希链 |
| 桌面端 | ✅ | Electron 同进程托管，Win/Mac 双平台 |
| 安卓播放端 | ✅ | Kotlin WebView 壳 + JS Bridge，自升级 |
| 开源发布 | ✅ | GitHub MIT，CI 自动出 exe/dmg/apk |

**一句话**：核心闭环已经跑通，且在安全性上已经超过 e 版。接下来的方向是**从"能用"走向"好用、耐用、有壁垒"**。

---

## 1. 排序原则

不按"技术上酷不酷"排，按这个公式排：

```
优先级 = (真实痛点强度 × 影响用户比例) ÷ 实现成本
```

同时守住项目铁律：**零依赖、免构建、局域网优先**。任何需要 `npm install` 一堆包或强制上云的方案，直接降级。

---

## 2. P0 · 强烈建议做（3 个月内）

### 2.1 播放证明与合规存证包 📄

**痛点**：数字标牌在商业场景最常见的纠纷是"广告到底播没播、播了多少次"。目前有日志，但拿不出**能给客户/监管看的东西**。

**做什么**：
- 终端上报每次播放的起止时间戳 + 素材 ID + 截屏抽样
- 生成 PDF 播放证明报告：时段、频次、终端、截图九宫格
- 报告带审计链 hash，可验证未被篡改
- 支持按客户/按素材/按时间段导出

**价值**：这是**能直接变现的功能**。广告位租赁、连锁品牌总部对分店的合规检查，都需要这个。e 版没有像样的实现。

**成本**：中。PDF 生成可用纯 JS 手写（已有 pdf 导出经验），不引依赖。

---

### 2.2 素材有效期与自动下线 ⏰

**痛点**：促销活动过期了，海报还在屏上挂着——这是数字标牌最高频的运营事故，没有之一。

**做什么**：
- 素材/节目支持设置 `validFrom` / `validUntil`
- 到期自动从播放列表移除，终端本地也做过期判断（防离线时继续播）
- 到期前 N 天在管理端推送提醒
- 过期素材归档区，不直接删除

**价值**：高频刚需，实现成本低，性价比最高的一项。

**成本**：低。schedule.js 加时间窗判断，播放引擎加本地过期兜底。

---

### 2.3 终端健康度与故障预警 🩺

**痛点**：屏黑了没人知道，等客户投诉才发现。现在只有"在线/离线"，太粗。

**做什么**：
- 采集：CPU/内存/存储剩余、温度、网络延迟、连续运行时长、WebView 崩溃次数
- 健康度评分（0–100），异常自动告警
- 告警渠道：管理端红点 + 可选 Webhook（企微/钉钉机器人）
- 存储不足自动清理最旧的已下线素材

**价值**：从"被动救火"变"主动运维"。50 台屏靠人肉巡检不现实。

**成本**：中。安卓端 Bridge 已有 `getNativeStatus`，扩展字段即可；服务端加评分模型和告警规则。

---

### 2.4 一键回滚与灰度下发 🔄

**痛点**：下发错内容，50 台屏同时出错，只能手忙脚乱一台台改。

**做什么**：
- 每次下发生成不可变版本快照
- **灰度下发**：先发 1–3 台试点屏，确认无误再全量
- **一键回滚**：任意时刻回到上一个版本，秒级生效
- 下发失败自动重试 + 失败清单

**价值**：这是把系统从"玩具"变成"生产级"的关键。运维安全感直接翻倍。

**成本**：中。store 已是 JSON 文档，加版本目录即可；下发逻辑加分批。

---

## 3. P1 · 值得做（6 个月内）

### 3.1 图片/视频内容 AI 审核 🖼️

**痛点**：现在的合规引擎只能查文本，图片里印着的违规内容抓不到——这是安全白皮书里明确的能力边界。

**做什么**：
- 上传时可选接入图审服务（本地 OCR 提取文字过词库，或对接第三方图审 API）
- 保持**可选、可离线降级**：不配置就退回纯文本审核，不破坏零依赖原则
- OCR 结果同样进合规三道闸

**成本**：中高。纯本地 OCR 需要模型文件（违背零依赖），建议做成"外部服务适配层"，用户自行决定接不接。

---

### 3.2 数据驱动的动态内容 📊

**痛点**：现在的节目是静态的。真实场景要显示"今日排队人数""实时库存""生产线良率"这类会变的数据。

**做什么**：
- 数据源组件：定时拉取 HTTP/JSON API、读取局域网内 CSV/Excel、接 MQTT
- 模板变量语法：`{{data.queue_count}}`
- 内置图表组件（纯 SVG 手绘，不引 Chart.js）：柱状/折线/环形/数字翻牌
- 数据源失败时的降级显示

**价值**：这是**跟纯播放器拉开差距的关键**。工厂看板、餐饮叫号、门店 KPI 大屏都需要。

**成本**：高。但价值也最高，是产品护城河。

---

### 3.3 多分支机构联邦 🏢

**痛点**：现在是单局域网。连锁品牌有 20 家门店，每家一套系统，总部管不过来。

**做什么**：
- 保持每店独立部署（不改局域网优先的铁律）
- 增加**总部聚合层**：各店服务端主动上报摘要到总部节点
- 总部可下发"全局节目"，各店自动同步
- 总部只读监看所有门店，本地故障不影响门店播放

**成本**：高。涉及跨网通信、离线容忍、冲突合并。

---

### 3.4 交互式节目 👆

**痛点**：触摸屏只当播放器用，浪费了。

**做什么**：
- 触摸热区、多级菜单导航
- 二维码动态生成（点击后展示优惠券/表单）
- 停留超时自动回主界面
- 交互埋点统计（哪个按钮被点了多少次）

**成本**：中。播放引擎已有事件体系，扩展交互组件即可。

---

### 3.5 素材智能压缩与转码 🗜️

**痛点**：运营直接传 4K 原片，50 台屏同时拉，内网被打满。

**做什么**：
- 上传时自动生成多档码率版本
- 按终端分辨率下发匹配档位
- 图片自动转 WebP
- 下发限速 + 错峰调度（夜间预下载）

**成本**：中。转码需要 ffmpeg（违背零依赖）——建议做成**可选外挂**：检测到系统有 ffmpeg 就启用，没有就原样下发。

## 4. P2 · 长期考虑（12 个月+）

| 功能 | 说明 | 备注 |
|---|---|---|
| 移动端 App | 手机审批、手机看监看墙、扫码开通终端 | PWA 即可，不必原生 |
| 模板市场 | 内置行业模板（餐饮/零售/医院/工厂），一键套用 | 提升首次上手体验 |
| AI 节目生成 | 输入文案 → 自动排版生成节目 | 需外部大模型，做成可选 |
| 多语言 | 界面 i18n + 节目多语言轮播 | 出海场景 |
| 电子价签联动 | 与 ESL 系统打通，价格统一变更 | 零售垂直 |
| 人流统计 | 接摄像头做客流计数，联动内容策略 | 涉隐私，需谨慎 |
| 节能优化 | 无人时自动降亮度/待机，有人靠近唤醒 | 需红外/雷达传感器 |

## 5. 明确不做的事

技术选型上守住边界，比堆功能更重要：

| 不做 | 原因 |
|---|---|
| 强制上云 | 违背"局域网优先、数据不出厂"的核心定位，也是相比 e 版的差异点 |
| 引入前端构建链（React/Vue/Vite） | 免构建是刻意选择：改完 F5 即生效，运维零门槛 |
| 引入数据库（MySQL/PG） | 50 台规模下 JSON 文档存储完全够用，备份=拷目录 |
| 引入 npm 生产依赖 | 零依赖 = 不会因为某个包被删/投毒而炸掉 |
| 做 SaaS 多租户计费 | 定位是自建自用系统，不是卖服务 |

## 6. 建议的执行顺序

```
第 1 个月  ├─ 素材有效期与自动下线        （低成本高价值，先摘果子）
           └─ 一键回滚与灰度下发           （生产级必需）

第 2 个月  ├─ 终端健康度与故障预警
           └─ 播放证明与合规存证包（第一版）

第 3 个月  └─ 播放证明报告完善 + P0 整体打磨、文档、回归测试

第 4–6 月  ├─ 数据驱动的动态内容          （护城河，值得花时间）
           ├─ 交互式节目
           └─ 素材智能压缩（ffmpeg 可选外挂）

第 7–12 月 ├─ 多分支机构联邦
           └─ 图片 AI 审核适配层
```

---

## 7. 一句话总结

灵屏现在已经**功能对标 e 版、安全超过 e 版**。接下来三个月的重点不是加更多花哨功能，而是把 **"素材有效期 + 灰度回滚 + 健康预警 + 播放证明"** 这四件事做扎实——它们决定了这套系统能不能真正扛住生产环境。做完这四件，再去攻**数据驱动的动态内容**，那才是拉开代际差距的东西。
